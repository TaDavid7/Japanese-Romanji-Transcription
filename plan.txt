To fix the "audio reference" we can set up an audio reference
audio -> Whispher -> kanji -> Mecab -> romanji (primary)
audio -> Wishper -> kana -> romanji (reference) 
*we can't just rely on this as we still want kanji for contexual meaning (as romanji can represent many different meanings) and
this route of the model has a lower accuracy
for each word:
    if the 2 readings disagree AND the known homograph is listed as a potential pronounciation of the kanji reading
        trust the kana
    else
        keep Mecab

Seems like Jamdict-data with pip not being installed caused this issue
AI reccomends this for workaround

# 1. download the sdist without installing
mkdir C:\temp\jd -Force
cd C:\temp\jd
python -c "import urllib.request as u, json; d=json.load(u.urlopen('https://pypi.org/pypi/jamdict-data/1.5/json')); url=[f['url'] for f in d['urls'] if f['filename'].endswith('.tar.gz')][0]; u.urlretrieve(url, 'jamdict_data-1.5.tar.gz'); print('downloaded')"

# 2. extract it
tar -xf jamdict_data-1.5.tar.gz
cd jamdict_data-1.5\jamdict_data

# 3. decompress the db (this is the step their installer fumbles)
python -c "import lzma, shutil; shutil.copyfileobj(lzma.open('jamdict.db.xz'), open('jamdict.db','wb')); print('decompressed')"

# 4. put it where jamdict looks by default
mkdir $env:USERPROFILE\.jamdict\data -Force
copy jamdict.db $env:USERPROFILE\.jamdict\data\jamdict.db

Issues why hybrid is worse
Single-mora substitutions dominate. 水 → み (0001), 日 → か (0002), 部 → ふ (0013), が → え (0007). The len(alt) >= 3 guard is clearly not in effect
Sokuon corruption. 0012 oborekakaxtsutte, 0017 sawaxtsutte, 0015 etaxtsutte. MeCab is emitting っ as its own token, jamdict returns a reading for it, and the substituted form romanizes as xtsu
It does sometimes work. 0011 fixed 木曾川/日本/ライン川 (kisogawa, nihon, raingawa — all correct vs kanji's wrong kisokawa/nippon). 0016 fixed 出生率 → shussee
